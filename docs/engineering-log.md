## 1. macOS에서 "픽셀 0" 판정이 깨진다

- **상황**: 하네스를 Linux 기기에서 만들고 승인받았다. 새 macOS 기기에서 이미 통과했던 A1을 다시 검증
- **증상**: A1 3개 상태가 모두 G6 실패(8~196px). 같은 앱끼리 비교(order 대 order, WEB 대 WEB)는 0px
- **원인**: 글자·SVG 가장자리 안티앨리어싱. 모양은 같고 가장자리 픽셀만 다름. macOS Chromium은 레이아웃의 서브픽셀 위치 차이에 래스터 결과가 민감해서, 같은 화면이라도 두 앱(Tailwind vs SCSS)의 서브픽셀 배치가 조금만 달라도 픽셀이 갈린다. Linux(FreeType, 힌팅 끔)에서는 같은 조건에서 0px
- **해결**: 서버(프록시·order·WEB_RECODE)는 호스트에 두고 **브라우저만** Linux 컨테이너(`mcr.microsoft.com/playwright:v1.63.0-noble`)에서 띄운다(`browser.sh`, `PARITY_BROWSER_WS`). 기준(fuzz·마스크·임계값)은 건드리지 않음
  - 하지 않은 것: fuzz 완화(기준 완화는 사람 승인 사항), macOS 전용 Chrome 플래그(승인 안 된 제3의 환경)
- **검증**: 기준 변경 없이 A1 3/3, 변이 전부 탐지, H2 자기 검증, 회귀 9/9
- **교훈**: 픽셀 판정 하네스는 **렌더링 플랫폼까지 고정해야** 재현된다. 기준 이미지를 저장하지 않고 매번 오라클을 띄우는 구조라, CPU 아키텍처(arm64)가 달라도 "두 앱이 같은 환경에서 같게 그려지는지"만 맞으면 된다

## 2·3. 컨테이너 브라우저 연결

- **localhost 유지**: 앱 URL을 `host.docker.internal`로 바꾸면 CORS·쿠키 도메인·`IS_STAGE` 판정·요청 정규화가 모두 달라진다. 컨테이너 안에서 `localhost:4000/4100/4101/4102`를 호스트로 넘기는 작은 TCP 포워더(`lib/browser-forward.cjs`)를 둬서 URL을 그대로 유지
- **vite `::1` 바인딩**: order(vite preview)가 `localhost`를 IPv6 `::1`에만 열어 Docker 게이트웨이(IPv4)에서 닿지 않음(`ERR_EMPTY_RESPONSE`). `--host 127.0.0.1`로 고정
- **실행 인자 무시**: `chromium.connect()`에 `x-playwright-launch-options` 헤더로 결정성 플래그를 넘겼지만, `run-server`는 보안상 `args`를 걸러낸다(`filterLaunchOptions`). `--unsafe`를 켜고(포트는 호스트 127.0.0.1에만 노출) 컨테이너 안 프로세스 명령줄(`docker exec ps`)로 플래그 적용을 확인. `chrome://version`은 headless shell에서 열 수 없고 CDP `Browser.getBrowserCommandLine`은 `--enable-automation` 없이는 거부됨

## 4. 빌드 직후 ECONNRESET

- **증상**: WEB_RECODE 프로덕션 빌드는 성공했는데 직후 `fetch failed: ECONNRESET`
- **원인**: 빌드를 `execFileSync`로 돌려 하네스 프로세스의 이벤트 루프가 수 분간 막힌다. 그 사이 프록시(Node http 서버, keep-alive 5초)가 유휴 소켓을 닫고, 빌드 직후 첫 요청이 닫힌 소켓을 재사용
- **해결**: 프록시 제어 요청(`proxySession`, `proxyControl`)은 네트워크 오류일 때만 새 연결로 1회 재시도. 같은 경합이 캡처 사이에서도 간헐적으로 나서 둘 다 적용
- **교훈**: 동기 블로킹 호출 + keep-alive 클라이언트 조합은 "가끔" 깨진다. 이전 Linux 기기에서는 드러나지 않았음

## 5. stage 5xx가 카세트에 박제

- 빌드 시점 카세트를 `--fill`로 채우는 중 stage가 일부 게시글에 500(외부 URL 크롤링 타임아웃)을 반환 → 카세트에 그대로 저장 → 이후 매 빌드 프리렌더 실패
- 직접 호출하면 200. 로컬 빌드 카세트에서 5xx 항목만 지우고 다시 채움. `STATUS.md`에 대처법 기록
- **교훈**: 기록·재생 프록시는 "기록 순간의 장애"도 결정적으로 재생한다. 보충(fill) 모드에서 5xx를 저장하지 않는 정책을 검토할 만함

## 6. 상태 탐색기 폭발

- **상황**: 사람이 쓴 스펙은 상태를 놓친다(과거 "UI가 다른데 통과" 사례). 그래서 오라클 화면의 클릭 가능한 요소를 자동으로 눌러 상태를 모으는 탐색기를 만듦
- **증상**: 상점 목록에서 카테고리를 바꿀 때마다 새로 나타난 상점 카드를 "새 요소"로 보고 전부 다시 눌러 수십 분 → 중단
- **해결 1차**: 후보를 "구조 서명"(nth 제거한 태그 경로)으로 묶어 반복 그룹은 대표만 누름 → **실패**: 카테고리 버튼 12개와 상점 카드 171개, 검색창이 태그 경로가 같아 184개가 한 그룹으로 묶여 카테고리 상태를 놓침
- **해결 2차**: 서명에 **조상 요소의 클래스**를 넣고 요소 자신의 클래스는 뺀다(선택된 항목만 클래스가 달라 그룹이 쪼개지는 것 방지). 반복 그룹(4개 이상)은 앞 2개만(첫 항목이 이미 선택된 카테고리일 수 있음). 깊은 단계에서는 부모 상태에 없던 **그룹**만 누르고, 1단계에서 "다른 화면으로 이동"으로 판명된 그룹은 다시 누르지 않음
- **결과**: 깊이 2 탐색 1분 34초, 상태 7개(초기·카테고리·정렬 시트·영업중·별점순·리뷰순)
- **남긴 것**: "데이터만 다른 상태"(카테고리 10개 등)의 자동 병합은 하지 않고 사람이 대표 상태를 고름 — 자동화보다 싸다

## 7·8. 검증 도구의 검증이 틀렸다 (변이 테스트)

- **상황**: 하네스가 차이를 잡는지 확인하려고 오라클 화면에 일부러 차이(4px 이동·색·굵기·아이콘 제거·글자 삽입·요청 누락·분석 이벤트 누락)를 넣어 FAIL이 나는지 본다
- **증상**: A2에서 위치·색·굵기·글자 변이 4종이 MISSED
- **원인**: 변이 대상이 "화면에 보이는 첫 텍스트" = **헤더 제목**("주변상점"). 그런데 G6는 헤더(위 60px)를 비교하지 않는다. 하네스가 놓친 게 아니라 변이가 비교 범위 밖을 건드림. A1에서는 우연히 헤더에 글자가 없어서 드러나지 않았다
- **해결**: 글자 변이는 본문 영역(헤더 아래)만 대상으로(아이콘 변이는 원래 그랬음). 앞 공백이 있는 문구(" 가게 정렬")에 공백을 넣으면 공백이 합쳐져 화면이 안 바뀌므로 첫 비공백 글자 뒤에 삽입
- **8번**: 검색 화면 "입력 전" 상태는 원래 API 요청이 없어 "요청 누락" 변이를 적용할 대상이 없는데 MISSED로 집계 → 오라클 상태에 주 요청이 있을 때만 적용(N/A 처리)
- **교훈**: 변이 테스트도 "변이가 실제로 비교 대상을 바꿨는가"를 먼저 확인해야 한다. 단위마다 변이를 돌려야 하는 이유

## 9. 루프 에이전트가 범위 밖 수정을 정확히 거부

- A2 첫 반복에서 구현 에이전트가 `needs-human`으로 멈춤: foundation 공유 API(`ShopListV3`)가 `{ sorter, filter }`를 항상 넣고, 직렬화 유틸이 `undefined`를 `"undefined"` 문자열로 보내 `sorter=undefined&filter=undefined`가 나감 → 6개 상태 전부 G2 실패 예정
- 에이전트는 화면 파일만 수정 가능하다는 규칙대로 공유 파일을 고치지 않고 근거(직렬화 결과 직접 확인)와 최소 수정안을 반환. 사람이 foundation 레이어에 수정 → `gh stack rebase` → 루프 재개 → 2회차 통과
- **교훈**: "수정 가능 파일 목록 + 범위 밖이면 멈춤" 규칙이 스택 PR 구조(공유 파일은 foundation)와 잘 맞물림

## 10. 회귀 카세트가 단위 진행에 따라 낡는다

- A2가 모바일 `/store`를 order 화면으로 바꾼 뒤, A3 회귀 검사에서 `store-list.mobile`이 기준(A2)·후보(A3) **둘 다** 렌더 실패. 새 화면이 부르는 `/v3/shops`가 A2 이전에 기록된 회귀 카세트에 없음(재생 모드 miss)
- 픽셀 차이는 0이라 판정 로직은 정상. 회귀 카세트를 `--fill --pages`로 보충. 이후 화면을 바꾸는 단위(A4)는 끝날 때 미리 보충
- 단위가 의도적으로 바꾸는 회귀 케이스는 `--skip <페이지>.<기기>`로 빼고 리포트에 남김(A2 `store-list.mobile`, A4 `store-detail.mobile`)

## 11. 원격 브라우저 연결이 남아 프로세스가 안 끝남

- 상세 화면 탐색이 15:26에 결과 파일까지 썼는데 프로세스가 40분째 살아 있음
- 상태 도달 실패(메뉴 카드 클릭 타임아웃) 시 `openPage`가 예외를 던지면서 브라우저를 닫지 않음. 로컬 브라우저였을 때는 프로세스 종료와 함께 정리됐지만 원격(WebSocket) 연결은 이벤트 루프를 붙잡음 → 실패 경로에서도 `browser.close()`

## 12. 비슷하게 vs 같은 라이브러리

- order 상세 이미지 뷰어는 Swiper(Navigation·Pagination·Zoom). WEB_RECODE에는 없어서 처음엔 "의존성 추가 금지, 보이는 모양만 재현"으로 지시
- 사용자 결정: Swiper를 써서 기능까지 동일하게. 실행 중 루프를 멈추고, 의존성은 공유 변경이므로 foundation 레이어에 추가(Zero-Install: `.pnp.cjs`·`.yarn/cache` 포함) → 스택 재정렬 → 미완성 작업은 임시 커밋으로 보존한 채 재개
- 포털로 body에 붙는 뷰어가 reset-css의 `body { line-height: 1 }`을 물려받아 페이지네이션 점이 4px 낮게 그려진 것을 픽셀 게이트가 잡음

## 13. 대소문자

- develop에는 `src/assets/svg/Store/`(대문자 6개)가 있는데 foundation 지침은 소문자 `store/`. macOS(대소문자 무시)에서는 한 폴더로 보여 `git add`가 대문자 경로로 기록되기도 함. 에이전트들이 `git ls-files`로 확인하고 인덱스에 소문자 경로로 직접 넣음
- Linux(CI·서버)에서는 두 폴더로 갈림. import가 각각 맞아 빌드는 되지만 전환 전 정리 과제로 남김

## 14. 기록 카세트의 개인정보

- 로그인 상태 기록(리뷰 작성 등) 중 `/v3/users/me` 응답에서 아이디·이메일·전화·학번은 키 이름 규칙으로 가려졌는데 **실명·전공은 그대로** 저장됨(`name`은 상점명에도 쓰여 키 이름만으로 가릴 수 없음)
- `login_id`·`student_number`가 있는 객체를 "사용자 객체"로 보고 그 안의 `name`·`major`·`gender`를 가림. 글자 수는 유지(`가가가`)해 레이아웃 불변
- 카세트 본문은 base64라 단순 문자열 검색으로는 확인이 안 됨 → 하네스 저장소 **이력 전체 blob(25개)을 디코딩**해 검사. 실명 커밋 이력 없음(걸린 "건축공학"은 공개 학과 목록)
- **교훈**: 가림 규칙은 키 이름 목록만으로는 부족하다. "기록 후 디코딩 검사"를 절차에 넣어야 한다

## 15. 공유 페이지와 로그인 회귀

- 리뷰 작성·수정·신고(A7~A9)는 데스크톱과 같은 페이지를 고친다. 그런데 회귀 게이트에 이 페이지들이 없고 로그인 상태도 지원하지 않았다 → 회귀 케이스에 `auth` 지원 추가, 로그인 상태 데스크톱 작성·수정·신고 3개 케이스 추가(테스트 계정 리뷰·다른 사람 리뷰 ID를 stage에서 찾아 고정)
- 이 케이스가 19번 문제를 잡았다

## 16. 기존 훅 재사용의 함정

- 모바일 리뷰 수정 화면이 데스크톱 `useEditStoreReview`를 재사용 → 그 훅이 성공 시 자체 토스트("리뷰 수정이 완료되었습니다.")를 띄워 order 토스트와 **두 개**가 뜸. 하네스는 제출(PUT)을 하지 않아 G3로는 드러나지 않음 — 구현 에이전트가 코드를 읽고 보고
- 공용 mutation 옵션(`reviewMutations.edit`)을 모바일 화면에서 직접 쓰고 order 토스트만 띄움. 데스크톱 훅은 불변

## 17. 비교 대상이 아닌 헤더가 상태 도달을 막음

- 리뷰 수정 "나가기 모달"은 헤더 뒤로가기로 연다. 접근성 이름이 order "뒤로가기 버튼", WEB_RECODE 공용 헤더 "뒤로가기"로 달라 후보에서 클릭 실패 → 에이전트가 공유 UI 수정 필요로 멈춤
- 헤더는 비교 대상이 아니므로 공유 UI를 바꾸지 않고 액션이 이름 후보 목록(`names`)을 받게 함

## 18. 포커스와 자동 스크롤

- 입력 후 입력창 포커스가 남은 상태에서 전체 페이지 스크린샷을 찍는 동안 **브라우저가 포커스 요소를 보이게 하려고** 오라클만 scrollY 29→71로 이동. 고정 헤더가 본문 비교 영역에 찍혀 실패. 스크립트 호출은 없었음(에이전트가 scrollTo 등을 훅으로 확인)
- 상태 마지막에 `{ "blur": true }`(포커스 해제 + 맨 위 스크롤) 액션

## 19. "develop 결함"이 아니었다 — React Suspense 300ms

- A8 회귀에서 데스크톱 리뷰 수정 페이지가 474,555px 차이. develop 원본 캡처에는 상단 헤더가 없고 A8에는 있음 → 처음엔 "develop의 헤더 누락 결함이 고쳐진 것"으로 보고 수용 여부를 사용자에게 물음
- 사용자 선택: **원인 먼저 조사**. 원본을 같은 조건으로 띄워 가짜 시계를 진행하며 DOM을 관찰: 헤더는 처음 `display: none !important`(React Suspense가 데이터 대기 중 숨김), 시계를 2초 진행하자 정상 노출, 60초까지 유지
- **원인**: 하네스 `settle`이 가짜 시계를 100ms씩 진행하며 요소 목록이 두 번 연속 같으면 정착으로 판단. React는 숨겼던 내용을 다시 보일 때 300ms 지연 타이머를 쓰므로 그 전에 "정착"으로 판단해 숨겨진 순간을 찍음. A8은 페이지 구조가 바뀌며 타이밍이 달라져 헤더가 보였을 뿐
- **해결**: 진행 단위를 500ms로. 회귀 12/12
- **교훈**: 회귀 차이를 "기존 버그가 고쳐졌다"로 해석하고 넘어갔다면 하네스 결함이 남았다. 원인 조사를 먼저 한 결정이 옳았다

## 20. 부드러운 스크롤은 실제 시간으로 움직인다

- 19번 수정으로 정착 대기가 길어지자 A4 기본 상태가 실패: 상세 이미지 캐러셀 자동 넘김 타이머가 돌기 시작했고, `scroll-smooth` 애니메이션은 **가짜 시계가 아니라 실제 시간**으로 움직여 넘어가는 중간 프레임이 앱마다 다르게 찍힘
- 캡처 중 CSS `scroll-behavior`와 JS `scrollTo/scrollBy/scroll/scrollIntoView`의 `smooth`를 즉시 이동으로 고정(애니메이션 차단과 같은 취지)
- **그러자 숨어 있던 실제 차이가 드러남**: 메뉴 그룹 탭 클릭 후 스크롤 분석 이벤트가 order 1회, WEB_RECODE 2회(G4). 이전에는 스크롤 애니메이션 타이밍이 이 차이를 가렸다 → A4 루프 재실행
- **교훈**: 비결정성을 하나 제거할 때마다 그 뒤에 가려져 있던 실제 차이가 나올 수 있다. 하네스 수정 후에는 이미 통과한 단위도 전부 다시 돌려야 한다

## 21. "조용히" 아무것도 안 돈 일괄 검증

- A1~A8 일괄 재검증을 `for u in "A1 a1" ...; do set -- $u; ...` 로 돌렸는데 출력이 비어 있음
- zsh는 따옴표 없는 변수를 단어로 나누지 않는다(bash와 다름) → 단위 이름에 공백 포함 문자열이 그대로 들어가 검증이 실행되지 않음. 출력에 PASS/FAIL 줄이 없다는 것을 확인하고 배열로 다시 실행
- **교훈**: "실패 없음"과 "실행 안 됨"을 구분하는 출력(케이스 수)을 항상 확인

## 22. 운영 소소한 것

- 루프 에이전트의 하네스 수정을 막는 권한 deny 규칙(`Edit(//…/koin-parity/**)`)이 셸의 상대 경로 `mv .claude/...`를 하네스 경로로 해석해 명령 전체를 막음 → 절대 경로 사용. 해제·복원은 파일 이름 변경
- 루프 실행 중 하네스 저장소에 파일을 만들면 검증 에이전트의 변조 검사(`git status --porcelain`)가 걸린다 → 문서 작성도 루프가 끝난 뒤에
- 워크트리에서 yarn이 안 쓰는 오래된 `.yarn/cache` zip 6개를 반복 삭제 → 변조 검사에 걸림. 저장소를 건드리지 않고 이 워크트리에서만 `git update-index --skip-worktree`

## 23. React Compiler가 분석 이벤트 수를 바꿨다

- 20번 수정 뒤 A4 메뉴 그룹 탭 클릭 상태에서 스크롤 로그가 order 1회, WEB_RECODE 2회
- 스크롤 로깅 훅 코드는 같았다. 차이는 훅에 넘기는 함수의 정체성: order는 `loggingFunc`을 렌더마다 새로 만들어 effect가 매 렌더 다시 구독되고, 그때 기준 스크롤 위치가 `scrollIntoView`로 이미 이동한 위치로 갱신돼 클릭 직후 스크롤은 거리 0으로 기록되지 않는다. WEB_RECODE는 `useCallback` + React Compiler(`reactCompiler: true`)가 함수를 고정해 재구독이 없어 이동 스크롤까지 기록
- 에이전트가 하네스 `capture()`로 scroll·resize·gtag 타임라인을 찍어 원인 확인. 해당 컴포넌트에만 `'use no memo'`를 두고 `useCallback`을 없애 order와 같은 이벤트 수(지표 연속성, 결정 D7)
- **교훈**: "같은 코드"를 옮겨도 프레임워크의 최적화(컴파일러 메모이즈)가 부수 효과의 타이밍을 바꾼다. 분석 이벤트를 게이트(G4)로 비교했기 때문에 잡혔다
